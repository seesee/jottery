# Inbox API

## Overview

The Inbox API provides a way to submit notes to a Jottery account programmatically, without needing the encryption password. This is useful for automation, integrations, and workflows where notes are generated by scripts, webhooks, or other tools.

**How it works:**

1. A user generates an **inbox token** from the web settings, user portal, or TUI CLI
2. External tools use this token to submit items to the inbox via a simple REST API
3. Submitted items are stored **unencrypted** on the server in a holding area
4. The user reviews inbox items in the web or TUI client during sync
5. Items can be **accepted** (encrypted into the main note corpus) or **deleted**
6. No editing of inbox items is supported — accept or delete only

**Security model:**

- Inbox tokens have limited scope — they can only submit new items to the inbox
- They cannot read, modify, or delete existing notes
- Items remain unencrypted on the server until accepted by the user
- When accepted, content is encrypted client-side before storage
- `showPreview` is always forced to `false` on acceptance (XSS prevention)
- Tokens can be revoked at any time; revoking does not delete existing items

## Prerequisites

- A Jottery account on a sync server
- At least one registered device (for reviewing and accepting items)
- An inbox token (see below)

## Generating an Inbox Token

### From the Web App

1. Open **Settings** (gear icon or `Ctrl+,`)
2. Navigate to the **Sync** tab
3. Find the **Inbox API** section
4. Click **Generate Token**
5. **Copy the token immediately** — it is shown only once
6. The section also displays a curl example for quick testing

### From the User Portal

1. Log in at `/user`
2. Go to **Account**
3. Find the **Inbox API** section
4. Click **Generate Token**
5. Copy the token and review the Quick Start guide

### From the TUI/CLI

```bash
# Generate a new token
jottery inbox-token generate -e user@example.com

# Check if a token exists
jottery inbox-token status -e user@example.com

# Revoke the current token
jottery inbox-token revoke -e user@example.com
```

Each command will prompt for your password. You can also pass `-s <server-url>` if you need to specify a non-default server endpoint.

## API Reference

### Submit a Note

```
POST /api/v1/inbox
Authorization: Bearer <inbox-token>
Content-Type: application/json
```

**Request body:**

| Field     | Type       | Required | Description                                           |
|-----------|------------|----------|-------------------------------------------------------|
| `content` | string     | Yes      | The note text (must not be empty/whitespace-only)     |
| `tags`    | string[]   | No       | Tags to assign to the note (default: `[]`)            |
| `source`  | string     | No       | Label identifying the submitter (e.g. `"cron-job"`)   |

**Response:** `201 Created`

```json
{
  "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "createdAt": "2025-06-15T10:30:00.000Z"
}
```

**Error responses:**

| Status | Reason                                     |
|--------|--------------------------------------------|
| 400    | Content is empty or missing                |
| 401    | Invalid, revoked, or missing token         |
| 413    | Inbox size quota exceeded                  |
| 429    | Inbox item count quota exceeded            |

### List Inbox Items

```
GET /api/v1/inbox
Authorization: Bearer <device-api-key>
```

Returns all inbox items for the authenticated user. Requires a device API key (not an inbox token).

**Response:** `200 OK`

```json
[
  {
    "id": "a1b2c3d4-...",
    "content": "My note content",
    "tags": ["tag1", "tag2"],
    "createdAt": "2025-06-15T10:30:00.000Z",
    "source": "curl",
    "sizeBytes": 42
  }
]
```

### Delete a Single Item

```
DELETE /api/v1/inbox/:id
Authorization: Bearer <device-api-key>
```

**Response:** `204 No Content`

Returns `404 Not Found` if the item does not exist or belongs to another user.

### Delete All Items

```
DELETE /api/v1/inbox
Authorization: Bearer <device-api-key>
```

Deletes all inbox items for the authenticated user.

**Response:** `204 No Content`

### Inbox Status

```
GET /api/v1/inbox/status
Authorization: Bearer <device-api-key>
```

Returns quota usage and limits.

**Response:** `200 OK`

```json
{
  "count": 5,
  "totalSizeBytes": 2048,
  "maxItems": 100,
  "maxSizeMb": 10
}
```

## Examples

### curl

```bash
# Submit a simple note
curl -X POST https://sync.example.com/api/v1/inbox \
  -H "Authorization: Bearer YOUR_INBOX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"content": "Remember to buy milk"}'

# Submit with tags and source
curl -X POST https://sync.example.com/api/v1/inbox \
  -H "Authorization: Bearer YOUR_INBOX_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "content": "Build passed for commit abc123",
    "tags": ["ci", "builds"],
    "source": "github-actions"
  }'
```

### Python (requests)

```python
import requests

ENDPOINT = "https://sync.example.com"
TOKEN = "your-inbox-token"

response = requests.post(
    f"{ENDPOINT}/api/v1/inbox",
    headers={
        "Authorization": f"Bearer {TOKEN}",
        "Content-Type": "application/json",
    },
    json={
        "content": "Meeting notes from standup",
        "tags": ["meetings", "standup"],
        "source": "meeting-bot",
    },
)

if response.status_code == 201:
    data = response.json()
    print(f"Created inbox item: {data['id']}")
else:
    print(f"Error {response.status_code}: {response.text}")
```

### Shell Script (Batch Import)

```bash
#!/bin/bash
# Import lines from a file as individual inbox items

ENDPOINT="https://sync.example.com"
TOKEN="your-inbox-token"

while IFS= read -r line; do
  [ -z "$line" ] && continue
  curl -s -X POST "$ENDPOINT/api/v1/inbox" \
    -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: application/json" \
    -d "$(jq -n --arg content "$line" '{content: $content, tags: ["imported"], source: "batch-import"}')"
  echo ""
done < notes.txt
```

### Shell Alias (Quick Capture)

```bash
# Add to your .bashrc/.zshrc
jot() {
  curl -s -X POST "https://sync.example.com/api/v1/inbox" \
    -H "Authorization: Bearer YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d "$(jq -n --arg c "$*" '{content: $c}')" | jq .
}

# Usage: jot Remember to review PR #42
```

### Integration Ideas

- **RSS/Atom feeds**: Poll feeds and submit new entries as inbox items
- **Webhooks**: Receive GitHub/GitLab notifications and forward to inbox
- **Cron jobs**: Daily summaries, system health reports, log digests
- **Email forwarding**: Parse emails and submit content to inbox
- **Voice transcription**: Transcribe voice notes and submit via API

## Accepting and Deleting Items

### Web App

1. After sync, an **Inbox (N)** indicator appears at the bottom of the note list sidebar
2. Click the indicator to open the Inbox Panel
3. For each item, you can **Accept** (encrypts and creates a note) or **Delete**
4. Use **Accept All** or **Delete All** for bulk operations
5. Delete All requires a confirmation step

### TUI

1. After sync, the inbox count appears in the status bar
2. Press `b` to open the inbox view
3. Navigate with `j`/`k` (or arrow keys)
4. `Enter` — accept the selected item
5. `d` — delete the selected item (with confirmation)
6. `A` — accept all items
7. `D` — delete all items (with confirmation)
8. `Esc` or `q` — close the inbox and return to the note list

## Quotas

Default limits per user:
- **100 items** maximum
- **10 MB** total size maximum

Quota enforcement:
- Item count is checked before each submission (HTTP 429 if exceeded)
- Total size is checked before each submission (HTTP 413 if exceeded)
- Size includes both content and serialised tags

### Checking Usage

- **Web**: Settings > Sync > Inbox API (usage shown when token is active)
- **User Portal**: Account page shows items count and size usage
- **API**: `GET /api/v1/inbox/status` returns count, total size, and limits
- **Admin**: User detail page shows inbox usage and quota settings

### Admin Configuration

Admins can adjust per-user quotas via the Admin Dashboard:

1. Navigate to the user's detail page
2. Edit **Inbox Max Items** (1–10,000) and **Inbox Max Size MB** (1–1,000)
3. Save changes — new limits are enforced immediately

## Security Considerations

- **Inbox tokens are separate from device API keys** — they have limited scope (submit only)
- **Content is stored unencrypted on the server** until accepted — this is by design, as the inbox token does not have access to the encryption key
- **`showPreview` is always forced to `false`** when accepting items — this prevents XSS via HTML/Markdown content
- **Tokens can be revoked at any time** — any integrations using the token will stop working immediately
- **Revoking a token does not delete existing items** — items must be deleted separately
- **User isolation** — inbox items are scoped to the token's user; other users cannot see or modify them
- **Inactive/unapproved users** — tokens for deactivated or unapproved accounts are rejected (HTTP 401)
